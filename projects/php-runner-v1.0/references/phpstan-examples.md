# PHPStan 2.x Examples

> Companion to `install_phpstan.sh`. PHPStan 2.x requires PHP 8.2+.
> Source: <https://phpstan.org/user-guide/getting-started>

## Basic usage

```bash
# Analyze a directory at level 5 (default)
php vendor/bin/phpstan analyse src

# Analyze multiple paths
php vendor/bin/phpstan analyse src tests

# Use a specific level
php vendor/bin/phpstan analyse src --level=8

# Use the strictest level
php vendor/bin/phpstan analyse src --level=max

# Show only the first N errors
php vendor/bin/phpstan analyse src --error-format=raw --no-progress | head -10
```

## phpstan.neon configuration

The default config generated by `install_phpstan.sh` (with absolute paths
already anchored to your project root):

```neon
# phpstan.neon - default config generated by PHP Runner v1.0
# Docs: https://phpstan.org/config-reference
#
# Memory limit: use --memory-limit flag (e.g. `phpstan analyse --memory-limit=1G`)
parameters:
    level: 5
    # Paths to analyse (absolute - PHPStan 2.x resolves relative paths
    # against its internal working dir, not the project root).
    paths:
        - /absolute/path/to/your/project/src
        - /absolute/path/to/your/project/tests
    excludePaths:
        - */vendor/*
        - */var/cache/*
        - */runtime/*
    reportUnmatchedIgnoredErrors: false
    parallel:
        maximumNumberOfProcesses: 2  # sandbox has 2 vCPU
```

**Why absolute paths?** PHPStan 2.x resolves relative paths against its
internal working directory (typically `/tmp` where the prebuilt binary runs),
not the project root. The `install_phpstan.sh` script automatically writes
absolute paths based on your `$PROJECT_DIR`.

**Why not `*/tmp/*` in excludePaths?** If your project lives in `/tmp/`, the
pattern would exclude everything. Use `*/var/cache/*` or `*/runtime/*` instead
to exclude common cache directories without catching `/tmp/your-project/`.

### Customizing for your project

```neon
parameters:
    level: 8
    paths:
        - src
        - tests
    excludePaths:
        - */vendor/*
        - */tmp/*
        - */cache/*
        - src/LegacyCode/*   # exclude legacy code
    reportUnmatchedIgnoredErrors: true
    parallel:
        maximumNumberOfProcesses: 2  # sandbox has 2 vCPU
    tmpDir: /tmp/phpstan-tmp
```

## Levels

PHPStan uses 10 levels (0-9) plus `max`. Each level includes the rules from
lower levels.

| Level | What it catches |
|---|---|
| `0` | Basic checks — return statements, callable, syntax. Always on. |
| `1` | Unknown methods on `unknownClass` (called on `mixed`) |
| `2` | Unknown methods on `$this`, unknown functions in `call_user_func` |
| `3` | Return type checks — function returns match declared type |
| `4 | Catch reachability, unreachable code, dead code |
| `5` | Argument count check, generics checks (basic) |
| `6` | Missing type hints — function/method signatures without types |
| `7` | Partially wrong unions — `int\|null` returned but always `int` |
| `8` | Calling methods on nullable types without null check |
| `9` | Be strict about `mixed` — needs explicit casts |
| `max` (10) | All rules, strictest. Recommended for new projects. |

**Recommendation:** Start at `level: 5` for legacy projects, ramp up to 8 over
time. For new projects, start at `level: 8`.

## Generating a baseline (for legacy code)

```bash
# Generate baseline from current issues
php vendor/bin/phpstan analyse src --level=5 --generate-baseline
```

This creates `phpstan-baseline.neon` listing all current errors. Include it in
your `phpstan.neon`:

```neon
includes:
    - phpstan-baseline.neon
parameters:
    level: 5
    paths:
        - src
```

Now PHPStan only reports NEW errors — old ones are ignored.

## Ignoring specific errors

```neon
parameters:
    ignoreErrors:
        # Ignore a specific error in a specific file
        - '#Call to an undefined method#' in src/LegacyCode.php

        # Ignore by message pattern globally
        - '#Variable \$.* might not be defined#'

        # Ignore by error identifier (more robust)
        -
            identifier: phpstan.method.variadic
            path: src/SomeFile.php
```

## Inline ignores

```php
<?php
// @phpstan-ignore-next-line (PHPStan method signature mismatch)
$undefined->method();

// @phpstan-ignore-line (PHPStan: variable might not be defined)
echo $maybeUndefined;

/** @phpstan-ignore-line */
$result = $unknown->someMethod();
```

## Common errors and fixes

### `Call to an undefined method X::method()`

```php
// Bad (level 5+):
$object = new \stdClass();
$object->nonExistent();  // Error: Call to an undefined method stdClass::nonExistent()

// Fix: declare the class properly or use type hints
class MyClass {
    public function existingMethod(): void { /* ... */ }
}
$object = new MyClass();
$object->existingMethod();  // OK
```

### `Method X::method() should return Y but returns Z`

```php
// Bad (level 3+):
function getName(): string {
    return null;  // Error: should return string but returns null
}

// Fix: return correct type, or change return type
function getName(): ?string {
    return null;  // OK — nullable return
}
```

### `Cannot call method on nullable type`

```php
// Bad (level 8+):
function getUpper(?string $name): string {
    return $name->toUpperCase();  // Error: $name could be null
}

// Fix: null-safe operator (PHP 8+)
function getUpper(?string $name): string {
    return $name?->toUpperCase() ?? '';  // OK
}

// Or: explicit null check
function getUpper(?string $name): string {
    if ($name === null) return '';
    return strtoupper($name);  // OK after null check
}
```

### `Variable $x might not be defined`

```php
// Bad (level 0+):
if (rand(0, 1)) {
    $var = 'value';
}
echo $var;  // Error: $var might not be defined

// Fix: initialize before, or always set in both branches
$var = null;
if (rand(0, 1)) {
    $var = 'value';
}
echo $var ?? 'default';  // OK
```

## Coverage reporting

PHPStan 2.x supports checking if your code is covered by tests:

```bash
# Generate coverage XML (requires xdebug or pcov)
php -d zend_extension=xdebug vendor/bin/phpstan analyse src --coverage
```

## PHPStan extensions (optional)

Common add-ons via Composer:

```bash
# Strict rules (more checks beyond level 9)
composer require --dev phpstan/phpstan-strict-rules

# PHPUnit rules (analyzes test code quality)
composer require --dev phpstan/phpstan-phpunit

# Symfony rules
composer require --dev phpstan/phpstan-symfony

# Doctrine rules
composer require --dev phpstan/phpstan-doctrine

# Beberlei assert rules
composer require --dev phpstan/phpstan-beberlei-assert
```

Add them to `phpstan.neon`:

```neon
includes:
    - vendor/phpstan/phpstan-strict-rules/rules.neon
    - vendor/phpstan/phpstan-phpunit/extension.neon
    - vendor/phpstan/phpstan-symfony/extension.neon
parameters:
    level: max
    paths:
        - src
        - tests
```

## Tips

- **Start with level 5** for existing codebases — it catches most bugs without
  requiring major refactoring.
- **Use baseline** for legacy code — don't fix everything at once, just prevent
  new issues.
- **Run PHPStan before PHPUnit** — static analysis is faster than tests.
- **Add to CI/CD** — runs in ~5s on a fresh sandbox.
- **Use strict rules** once at level 8 — they enforce PHP best practices.
- **Use `--no-progress`** in CI logs — cleaner output without the spinner.
- **Use `-v`** for verbose output when debugging.
